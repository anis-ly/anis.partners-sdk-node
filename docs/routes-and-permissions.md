| `wallets.get(walletId)`                                     | `GET /v1/wallets/{walletId}`                                               | `wallets:read`                                                 | SafeRead              | none       |

The full published route and error contracts are checked against the SDK's route table in the contract drift tests. For a request to be considered, Anis first validates its signature, then checks the required permission, source network, and resource access. A permission authorizes a capability; it does not override wallet grants, account state, purchase limits, or business rules. Lists count as read calls for the route's permission. `list()` follows continuation cursors; use a `listPage({ cursor, signal })` method when the application needs to control page boundaries. Pass a returned cursor back exactly as received; omit `cursor` for the first page and pass `signal` to cancel the request.

Every Partner API route counts toward `requests`. Orders also count toward `orders`; card and invoice reveals also count toward `reveals`. Enrollment requests and the public signing-key document are outside those usage counters.

## Before Anis evaluates the business request

Anis validates request shape, signature and body digest, credential state and freshness, nonce freshness, rate limits, source network, permission, and wallet grant before making an order decision. The order of these checks is not part of the contract, so do not rely on which refusal appears first. Network or permission refusals use `insufficient_scope`; wallet access uses `wallet_not_granted`. The signature self-check reports what Anis received when a proxy or local request builder may have changed the signed values.
