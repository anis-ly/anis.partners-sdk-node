## Adversarial review regressions

| Review finding                                                         | Node behavior and regression test                                                                                                                                                                                                                                           |
| ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1: host telemetry failures changed completed order results            | `test/operations/order-outcomes.test.ts` — `returns delivered credentials when every host logger call throws`; order reporting is outside purchase error handling and logger, metric, and span calls are isolated.                                                          |
| F2: repeated replay headers were misclassified                         | `test/operations/order-outcomes.test.ts` — repeated `true` values classify both successful and refused orders as replayed.                                                                                                                                                  |
| F3: native inspection exposed secrets                                  | `test/observability/redaction.test.ts` and `test/enrollment/enrollment-client.test.ts` — inspection redacts credentials, nested results, signed headers, and the enrollment token while JSON serialization remains unchanged.                                               |
| F4: encoded response bytes could differ from the signed bytes          | `test/client/pipeline-rules.test.ts` and `test/verification/http-signing-key-source.test.ts` — encoded answers are discarded and requests ask for identity encoding.                                                                                                        |
| F5: redirects could move a signed request                              | `test/client/transport-review.test.ts` and `test/verification/http-signing-key-source.test.ts` — API and key-document fetches use manual redirects.                                                                                                                         |
| F6: noncanonical or trailing signature data was accepted               | `test/internal/base64url.test.ts` and `test/verification/partner-response-verifier.test.ts` — decoders require canonical encodings and the full `sig1=:<base64>:` field. Node is intentionally stricter than .NET here, whose parser ignores trailing signature-field text. |
| F7: HTTP could replace the unsigned key document                       | `test/client/client-options.test.ts` — HTTPS is required except on loopback. This is intentionally stricter than .NET, which permits HTTP authorities.                                                                                                                      |
| F8: shared cache write access is a trust boundary                      | `docs/getting-started.md` — the serverless cache guidance says only the application should be able to write signing-key entries.                                                                                                                                            |
| N1: low-level transport skipped verification on the key-document route | `test/client/transport-review.test.ts` — a key-document route paired with `/v1/profile` rejects an unsigned answer.                                                                                                                                                         |
| N2: enrollment could serialize private JWK material                    | `test/enrollment/enrollment-client.test.ts` — private members are rejected before sending, and accepted submissions contain only public coordinates and validity dates.                                                                                                     |
| N3: enrollment JSON posts omitted Content-Type                         | `test/enrollment/enrollment-client.test.ts` — both key and proof posts carry `application/json`.                                                                                                                                                                            |
| N4: key-document member types and null `d` were parsed inconsistently  | `test/verification/partner-jwk.test.ts` — member types are checked and `d: null` is treated as absent.                                                                                                                                                                      |
